# Data Dictionary — `properties_v2`

Generated by the data-layer ETL (`scripts/etl/01_parse_raw_to_csv.ts` → `transform.ts` →
`scripts/etl/02_load_properties_v2.ts`) from the NYC DOF FY2027 PTS Property Master File. See
`db/pts_property_master_layout.md` for the raw 139-field source layout and
`db/schema.sql` for the literal DDL.

## Source & inclusion rule

Two raw files, tab-delimited, 139 fields each (see `db/pts_property_master_layout.md`):

- `PROPMAST_TC1_2027_FIN.txt` — Tax Class 1 (1–3 family homes), 706,713 rows.
- `PROPMAST_TC234_T2027_FIN.TXT` (inside `fy27_tc234.zip`) — Tax Classes 2/3/4, 461,249 rows.

**Inclusion rule: every row in both files.** Direct inspection of `RECTYPE` (field 7) confirms
100% of rows in both files are `RECTYPE=1` ("ordinary real estate") — there are zero REUC
(`RECTYPE` 2/3) rows in either file. So no filtering happens at all; the canonical set is simply
the union of both files. 706,713 + 461,249 = **1,167,962**, which matches the previously-verified
canonical row count of the old `properties` table exactly. `transform.ts`'s `transformRow()`
still defensively guards on `RECTYPE === "1"` in case a future year's extract ever includes REUC
rows.

## Primary key / BBL de-duplication

The old `properties` table had 3,791 duplicate-BBL groups (8,017 rows). Root cause, confirmed by
inspecting the raw PARID field: **EASE (easement) codes**. NYC DOF assigns separate PTS records
to the same block+lot for right-of-way / utility easements that sit on top of a parent parcel
(e.g. a DOT, Metro-North, or NYC DEP easement crossing another owner's lot) — same standard
10-digit BBL, different `EASE` code (A/B/E/F–M/N/P/R/S/U), different owner/building class/values.
It is **not** condo-unit duplication — condo units already have distinct LOT numbers and were
never duplicated.

Resolution: `properties_v2` keeps the standard 10-digit `bbl` (boro+block+lot) as-is (NOT unique
— matches the public BBL standard other systems join on) and adds `ease_code` + a synthetic
`bbl_full` (`bbl` + `ease_code`) as the actual `UNIQUE` row key. Verified: `bbl_full` is 100%
unique across all 1,167,962 rows (zero collisions).

## Columns

| Column | Type | Derivation |
|---|---|---|
| `id` | SERIAL PK | — |
| `bbl` | VARCHAR(10) | `BORO(1) + BLOCK(5, zero-padded) + LOT(4, zero-padded)`. Standard NYC BBL. Not unique alone. |
| `ease_code` | VARCHAR(1) | Raw `EASE` field, null for the ordinary (non-easement) parcel row. |
| `bbl_full` | VARCHAR(11), UNIQUE | `bbl + ease_code`. The true row key. |
| `borough_code` / `borough_name` | VARCHAR | Raw `BORO` (1–5) mapped to Manhattan/Bronx/Brooklyn/Queens/Staten Island. |
| `block` / `lot` | VARCHAR | Raw `BLOCK` / `LOT`, trimmed (not re-padded — `bbl` has the padded version). |
| `house_number_lo` / `house_number_hi` | VARCHAR | Raw `HOUSENUM_LO` / `HOUSENUM_HI`. |
| `street_name` | VARCHAR(30) | Raw `STREET_NAME`, trimmed. |
| `full_address` | VARCHAR(60) | `"{lo}-{hi} {street}"` if hi≠lo, else `"{lo} {street}"`, else just `{street}`. |
| `zip` | VARCHAR(5) | Raw `ZIP_CODE`, first 5 digits. **A literal `"0"` in the raw field (≈24K rows, mostly government/park/utility parcels with no mailing address) is normalized to `NULL`**, not stored as a fake zip — see `DATA_QUALITY_REPORT.md`. |
| `owner_raw` | TEXT | Raw `OWNER` field (source is itself truncated/fixed-width at 80 chars by DOF — see Known Limitations below), untruncated by us (old table truncated to VARCHAR(60), which is the bug this fixes). |
| `owner_normalized` | TEXT | `lib/owners/normalize.ts::normalizeOwnerName()` — uppercased, punctuation stripped, LLC/INC/CORP/CO/ASSOC/ASSN suffix variants canonicalized. Used for exact-match owner consolidation and as the GIN-trigram search column. |
| `owner_entity_type` | VARCHAR(24) | `lib/owners/classify.ts::classifyOwnerEntityType()`. One of: Individual, LLC, Corporation, Partnership, Trust/Estate, Government, Nonprofit/Institution, Cooperative corporation, Housing company, Unknown/Other. |
| `owner_group_id` | INTEGER FK → owner_groups | Set inline during load (see `OWNER_CONSOLIDATION_METHODOLOGY.md`); null for ungrouped (Individual/Unknown/Other/singleton private) owners. |
| `tax_class` | VARCHAR(2) | `FINTAXCLASS`, falling back to `TENTAXCLASS` if blank. |
| `building_class` | VARCHAR(4) | Raw `BLDG_CLASS`. |
| `building_class_description` | TEXT | Looked up from `db/building_class_codes.json` (curated DOF code list); falls back to `"{letter category} - Type {code}"` for codes not individually curated. |
| `property_type` | VARCHAR(32) | Derived rollup — see `derivePropertyType()` in `transform.ts`. Coop detection uses the raw `COOP_NUM` field (>0) rather than building-class guessing, taking precedence over class-letter rules. Values: one-family, two-family, small multifamily, walk-up apt, elevator apt, condo, coop, office, retail, industrial, hotel, parking/garage, mixed-use residential, utility, vacant land, government/institutional, entertainment/assembly, other. |
| `residential_units` | INTEGER | Raw `COOP_APTS` (DOF's residential-unit-count field despite the name). |
| `total_units` | INTEGER | Raw `UNITS`. |
| `commercial_units` | INTEGER | `total_units − residential_units` when `total_units ≥ residential_units`, else null. |
| `year_built` | SMALLINT | Raw `YRBUILT`, kept only if in `(1400, 2100]` (guards against garbage/zero values). |
| `lot_area` | INTEGER | Raw `LAND_AREA`. |
| `building_area` | INTEGER | Raw `GROSS_SQFT`. |
| `market_value` | BIGINT | `FINMKTTOT`, falling back to `TENMKTTOT`. |
| `assessed_value` | BIGINT | `FINACTTOT`, falling back to `TENACTTOT`. |
| `taxable_value` | BIGINT | `FINTXBTOT` (what tax is actually billed on). |
| `exempt_value` | BIGINT | `FINACTEXTOT`. |
| `value_band` | VARCHAR(16) | `<$500K / $500K–1M / $1M–2M / $2M–5M / $5M–10M / $10M–20M / $20M–50M / $50M+`, bucketed on `market_value`. |
| `latitude` / `longitude` | DOUBLE PRECISION | **NULL for all rows currently.** Reserved for a later wave to fill from MapPLUTO centroids. |
| `geocoding_status` | VARCHAR(16) | Defaults `'pending'` for every row. Set to `'geocoded'` / `'failed'` / `'not_applicable'` by the future geocoding wave. |
| `coop_number` | INTEGER | Raw `COOP_NUM`, null if 0/blank. |
| `source_year` | VARCHAR(8) | `'FY2027'` for all rows. |
| `source_dataset` | VARCHAR(64) | `'PROPMAST_TC1_2027_FIN'` or `'PROPMAST_TC234_T2027_FIN'`. |
| `created_at` | TIMESTAMPTZ | Load time. |

### Columns NOT stored (storage-constrained trade-off)

`value_per_resid_unit`, `value_per_total_unit`, `value_per_bldg_sqft` are **computed by the ETL**
(present in the intermediate CSV and in `data/aggregates.json` / `data/insights.json`) but are
**not** properties_v2 columns — see "Storage constraint" in `DATA_QUALITY_REPORT.md`. Compute
them on read (`market_value / residential_units`, etc. — cheap integer/float math) in any API
route that needs a per-property value.

## Owner tables

See `OWNER_CONSOLIDATION_METHODOLOGY.md` for `owner_groups` / `owner_aliases` semantics.

## Building class codes

`db/building_class_codes.json` — curated NYC DOF building classification list (`letters`: broad
category per first letter; `codes`: exact description for ~210 individually curated 2-character
codes covering every code actually observed in the FY2027 data). Codes not in the curated list
fall back to `"{letter category name} - Type {code}"`.

## Known limitations

- **Source-truncated owner names.** The raw `OWNER` field is fixed-width at 80 characters in the
  DOF file itself — some trust/LLC names are cut off mid-word at the source (e.g. `"...SHEP
  ARD LIV TR"`). `properties_v2.owner_raw` stores the full 80-char value untruncated (fixing the
  old table's *additional* 60-char truncation bug), but cannot recover characters DOF never
  included in the extract.
- **`UNAVAILABLE OWNER`** appears literally in the raw data for 11,946 rows (mostly REUC-adjacent
  or protected parcels) — classified `Unknown/Other`, treated as privacy-safe to display (no
  personal data to protect) since it's a placeholder, not a real name.
- **Owner field sometimes contains an address, not a name** (e.g. `"246 EAST 32ND STREET"`) — a
  DOF data-entry artifact seen in a small number of rows, classified `Unknown/Other` since it
  doesn't match any entity pattern and isn't a plausible personal name either.
- **`geocoding_status`** is `'pending'` for 100% of rows — no lat/long yet, deferred to a later
  wave.
- **Partial DB load.** See `DATA_QUALITY_REPORT.md` "Storage constraint" — `properties_v2`
  currently holds Staten Island + Bronx (246,465 of 1,167,962 rows) in Neon due to the project's
  storage cap; `data/aggregates.json` / `insights.json` / `data/borough/*.json` are computed from
  the FULL 1,167,962-row CSV and are NOT subject to this limitation.
